# DC 클리너

디시인사이드 **본인 계정**의 글, 댓글, 방명록을 조건에 맞춰 한꺼번에 지워 주는 개인용 iPhone/iPad 앱입니다.

몇 년 동안 쌓인 글과 댓글을 하나씩 지우기는 어렵습니다. 이 앱은 "2023년 이전 댓글만", "특정 갤러리 글은 빼고"처럼 조건을 정해 두면, 디시가 막지 않는 속도로 천천히 대신 지워 줍니다. 지우기 전에 내용을 기기에 백업해 두고, 남기고 싶은 글은 보호 목록으로 지켜 줍니다.

> **상태: 1~12단계 구현 완료, 실기기 검증 전.** 자동 테스트(127개)는 모두 통과하지만, 실제 디시 서버로 로그인하고 지우는 흐름은 아직 기기에서 끝까지 확인하지 않았습니다. 처음에는 적은 개수로 시험해 보세요. ([처음 써 볼 때](#처음-써-볼-때-권장-순서))

## 이런 앱입니다

- **네이티브 iOS 앱**: 모든 화면을 React Native 네이티브 컴포넌트로 만들었습니다. 웹앱이나 웹뷰 래퍼가 아니고, 설치하면 브라우저 없이 단독으로 동작합니다.
- **서버가 없습니다**: 앱이 디시인사이드와 직접 통신합니다. 개발자 서버, 프록시, 분석 도구, 광고가 없습니다.
- **내 글만 지웁니다**: 로그인한 계정의 갤로그에 있는 내 글, 댓글, 방명록만 대상으로 합니다. 다른 사람 글을 수집하는 기능은 없습니다.
- **iOS 26 리퀴드 글래스 디자인**: 탭바, 내비게이션 바, 카드, 버튼이 Apple 기본 글래스 스타일을 따릅니다. iOS 26 미만에서는 반투명 블러로, "투명도 줄이기"를 켠 기기에서는 불투명 배경으로 자동 대체됩니다. 다크 모드를 지원하고, 아이콘은 전부 윤곽선 SF Symbols입니다.
- **(!) 도움말**: 모든 설정과 주요 버튼 옆의 (!)를 누르면 기능 설명과 주의사항이 나옵니다.
- **한국어 전용**, iPhone과 iPad 모두 지원합니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 로그인 | 디시 식별 코드(아이디)로 로그인합니다. 비밀번호는 iOS 키체인에만 저장되고, 로그인이 풀리면 자동으로 다시 로그인합니다. |
| 캡챠 | 자동입력 방지 코드가 나오면 직접 입력하거나, 2Captcha / Anti-Captcha / CapSolver API 키로 자동 처리합니다. 자동 처리가 실패하면 알림과 함께 수동으로 바뀝니다. |
| 삭제 프리셋 | 대상(글/댓글/방명록, 여러 개 선택), 갤러리(전체/포함/제외, 일반·마이너·미니), 기간, 키워드, 추천수·조회수 조건을 이름을 붙여 저장합니다. 복제와 삭제도 됩니다. |
| 미리보기 (Dry-run) | 지우기 전에 삭제될 항목 수와 목록, 예상 소요 시간을 보여주고 확인을 받습니다. |
| 보호 목록 | 미리보기 목록에서 길게 누르거나 밀어서 지정합니다. 어떤 경로로 실행해도 절대 지우지 않습니다. JSON으로 내보내고 가져올 수 있습니다. |
| 방명록 | 내 갤로그에 달린 방명록을 연도별(여러 연도, 범위, N년 이전 전부)과 월, 작성자, 키워드로 골라 지웁니다. |
| 삭제 전 백업 | 지우기 직전에 제목, 본문, 작성 시각을 기기에 저장합니다 (JSON, 또는 읽기용 HTML + JSON). 공유 시트로 파일 앱이나 AirDrop에 내보내고, 용량 확인과 오래된 백업 정리를 할 수 있습니다. |
| 삭제 엔진 | 한 건씩 지우고 결과를 검증합니다. 앱이 꺼져도 처리한 위치부터 이어서 재개하고, 실패한 항목은 다시 시도합니다. |
| 자동 일시정지 / 중단 | 연속 실패, 차단 의심 응답, 디시 구조 변경을 감지하면 스스로 멈추고 알림을 보냅니다. |
| 백그라운드 / 스케줄 | 앱을 닫아도 iOS가 허락하는 만큼 이어서 처리합니다. 요일과 시각을 정해 자동 실행할 수 있습니다. |
| 앱 잠금 | Face ID / Touch ID로 앱을 잠그고 (기기 암호로 대체 가능), 앱 전환 화면을 가립니다. 삭제 시작, 백업 삭제, 계정 보기에 재인증을 요구할 수 있습니다. |
| 기록 / 통계 | 삭제 이력 검색과 JSON/CSV 내보내기, 갤러리별·기간별 통계를 봅니다. |
| 설정 백업 | 프리셋, 보호 목록, 설정을 JSON 파일 하나로 옮깁니다 (비밀번호와 API 키는 빠집니다). |
| 디버그 모드 | 요청 요약(비밀값은 가림)과 크래시 기록을 기기에만 남기고, 복사하거나 내보냅니다. |
| 단축어 | `dccleaner://` 주소로 프리셋 실행, 일시정지, 재개, 상태 보기를 할 수 있습니다. |
| 위젯 / Live Activity | 홈 화면 위젯(최근 결과)과 잠금화면·Dynamic Island 진행률. **실험적이라 별도 IPA로 제공합니다.** |

## 안전 원칙

삭제한 글은 되돌릴 수 없습니다. 그래서 수동 실행, 스케줄, 단축어 등 **모든 실행 경로**에서 아래 순서를 똑같이 지킵니다.

```
확인 → 백업 → 보호 목록 검사 → 삭제 → 응답 검증
```

- **확인 없이 지우지 않습니다.** 수동 실행과 단축어는 앱 안에서 확인 창을 거칩니다. 스케줄은 미리보기 없이 돌기 때문에, 스케줄을 켤 때 따로 한 번 더 확인받습니다.
- **성공은 검증한 뒤에만 셉니다.** 디시 응답이 "성공"이어야 하고, 빈 응답은 "미확인"으로 둡니다. 10건마다(엄격 모드는 매번) 실제로 사라졌는지 다시 확인하고, 남아 있으면 바로 멈춥니다.
- **디시 구조가 바뀐 것 같으면 즉시 멈춥니다.** 응답 형식이 예상과 다르면 잘못 지우는 일이 없도록 작업을 중단하고 "앱 업데이트가 필요할 수 있습니다"와 디버그 정보를 보여줍니다.
- **매니저 차단 경고는 자동으로 넘기지 않습니다.** 디시가 "지우면 매니저에게 차단된다"고 경고하는 항목(말머리 삭제 제한, 공지글 댓글 등)은 건너뜁니다.
- **백업 필수 모드(기본 켜짐)**: 백업에 실패한 항목은 지우지 않습니다.

## 알아 두세요

- **느립니다 (의도된 동작입니다).** 디시는 1분에 약 20회 넘게 요청하면 일시적으로 막습니다. 그래서 앱은 요청마다 4~7초를 쉬고, 1분에 5건 안팎을 지웁니다. 항목이 1만 개를 넘으면 하루 이상 걸릴 수 있습니다.
- **차단 위험이 있습니다.** 보수적인 속도로 요청하지만, 디시가 계정이나 IP를 제한할 가능성이 완전히 없지는 않습니다. 요청 간격을 너무 줄이지 마세요.
- **iOS 백그라운드 제한**: iOS는 앱이 뒤에서 오래 실행되는 것을 허용하지 않습니다. 앱을 화면에 켜 두면 가장 빠르고(실행 중에는 화면이 꺼지지 않음), 앱을 닫으면 iOS가 가끔 깨워 줄 때 조금씩 이어서 처리합니다. 스케줄도 정확한 시각이 아니라 "그 시간 이후 가능한 때"에 실행됩니다.
- **지속 실행 모드 (사이드로드 전용, 기본 꺼짐)**: 무음 오디오로 앱을 계속 깨워 둡니다. 배터리를 많이 쓰고 App Store 심사를 통과할 수 없는 방식입니다.
- **"내가 남긴 방명록"은 지울 수 없습니다.** 다른 사람 갤로그에 쓴 방명록은 디시가 목록을 주지 않아 찾을 수 없습니다.
- **2차 인증(OTP) 계정은 아직 지원하지 않습니다.**
- **디시가 사이트를 바꾸면 동작이 멈출 수 있습니다.** 공식 API가 아니라 모바일 웹이 쓰는 요청을 그대로 쓰기 때문입니다.
- **개인정보는 기기 밖으로 나가지 않습니다.** 외부로 나가는 데이터는 디시인사이드와의 통신, 그리고 자동 캡챠를 켰을 때 그 서비스로 보내는 캡챠 이미지뿐입니다.

## 설치하기 (Windows, Mac 없음)

Mac이 없어도 됩니다. IPA(설치 파일)는 GitHub의 macOS 서버가 만들고, Windows PC에서는 Sideloadly로 기기에 설치합니다.

### 1단계. IPA 받기
1. 이 저장소의 **Actions** 탭에서 **iOS unsigned IPA**를 엽니다.
   - 새로 빌드하려면 **Run workflow**를 누릅니다. `main`에 코드가 올라가면 자동으로도 실행됩니다.
   - 한 번에 약 20분 걸립니다.
2. 가장 최근의 초록색 체크 표시가 있는 실행을 엽니다.
3. 맨 아래 **Artifacts**에서 받습니다.

   | 파일 | 내용 |
   |---|---|
   | `DC-Cleaner-unsigned-ipa` | **기본 앱 (권장)** |
   | `DC-Cleaner-widgets-unsigned-ipa` | 위젯 + Live Activity 포함 (실험적). 이 빌드가 실패했다면 받을 파일이 없습니다. |

4. 받은 zip을 풀면 `.ipa` 파일이 나옵니다.

### 2단계. Sideloadly로 설치
1. Windows PC에 **iTunes**(Apple 웹사이트 버전 권장)와 **iCloud**를 설치합니다. Sideloadly가 기기를 인식하는 데 필요합니다.
2. [Sideloadly](https://sideloadly.io)를 설치하고 실행합니다.
3. iPhone/iPad를 USB로 연결하고, 기기에서 "이 컴퓨터를 신뢰"를 누릅니다.
4. Sideloadly 창에 `.ipa` 파일을 끌어다 놓습니다.
5. **Apple ID** 칸에 본인 Apple ID를 넣고 **Start**를 누릅니다. 처음이면 Apple ID 비밀번호를 묻습니다(Sideloadly가 Apple에 서명을 요청할 때 씁니다).
6. 설치가 끝나면 기기에서:
   - **설정 > 일반 > VPN 및 기기 관리**에서 본인 Apple ID를 눌러 **신뢰**합니다.
   - iOS 16 이상이면 **설정 > 개인정보 보호 및 보안 > 개발자 모드**를 켜고 재시동합니다.

> **무료 Apple ID 제한**: 무료 계정으로 서명한 앱은 **7일 뒤에 실행되지 않습니다.** 7일 안에 Sideloadly로 다시 설치(재서명)하면 데이터는 그대로 남습니다. 유료 Apple Developer 계정(연 $99)이면 1년입니다.
>
> **위젯 빌드 주의**: 위젯 확장은 App Group 기능을 씁니다. 무료 Apple ID로는 확장이 들어간 앱 서명이 거절되거나 위젯이 데이터를 못 읽을 수 있습니다. 그런 경우 기본 IPA를 쓰세요.

AltStore를 써도 됩니다: AltServer(Windows)를 설치한 뒤 기기의 AltStore에서 `.ipa`를 열면 됩니다.

### (선택) EAS Build — Apple Developer 계정이 있을 때
서명된 IPA를 Expo 클라우드에서 만들 수 있습니다.
```powershell
npm install
npx eas-cli@latest login
npx eas-cli@latest build --platform ios --profile preview
```
- `development`: 개발용 빌드 (expo-dev-client)
- `development-simulator`: 시뮬레이터용 (Mac에서만 의미 있음)
- `preview`: 내부 배포(ad hoc). 기기 UDID 등록이 필요합니다.
- `production`: App Store용 (지속 실행 모드 때문에 심사를 통과하지 못할 수 있음)
- 위젯 포함 빌드는 PowerShell에서 `$env:DC_APPLE_TARGETS='1'`을 설정한 뒤 빌드합니다. 이때 `package.json`의 `expo.autolinking`을 `{ "nativeModulesDir": "./native-modules" }`로 바꿔야 합니다 (Actions의 위젯 잡과 같은 설정).

## 처음 써 볼 때 (권장 순서)

1. **로그인**: 설정 > 디시 계정에서 식별 코드와 비밀번호로 로그인합니다. 캡챠가 나오면 시트에 입력합니다.
2. **시험용 프리셋**: 프리셋 탭 > 새 프리셋에서 대상은 "댓글"만, 기간은 "특정 날짜 이전"으로 아주 오래된 날짜를 넣어 몇 개만 걸리게 만듭니다.
3. **미리보기**: 프리셋을 눌러 미리보기 > **목록 새로 수집**을 합니다(글이 많으면 수십 분 걸립니다). 남길 항목은 길게 눌러 보호합니다.
4. **실행**: "N개 삭제 실행" → 확인. 홈 탭에서 진행 카드를 보며, 중간에 일시정지했다가 이어서 실행해 봅니다.
5. **확인**: 디시 웹에서 실제로 지워졌는지 보고, 기록 탭 > 백업에서 백업 파일을 열어 봅니다.
6. 문제가 없으면 조건을 넓혀 사용합니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| "식별 코드 또는 비밀번호가 일치하지 않습니다" | 디시가 보낸 문구입니다. 디시 모바일 웹에서 같은 정보로 로그인되는지 먼저 확인하세요. 식별 코드는 로그인할 때 쓰는 아이디입니다. |
| "로그인 결과를 확인하지 못했습니다 (응답 …)" | 디시 로그인 응답 형식이 예상과 다릅니다. 설정 > 디버그 모드를 켜고 다시 시도한 뒤, 디버그 기록을 복사해 이슈로 남겨 주세요. |
| "요청이 너무 많아 잠시 막혔습니다" / "요청 한도에 걸렸습니다" | 몇 분 기다렸다가 이어서 실행하세요. 설정 > 요청 간격을 늘리면 덜 걸립니다. |
| "디시 구조가 바뀐 것 같습니다" | 앱이 안전을 위해 멈춘 상태입니다. 홈의 "디버그 정보 복사"로 내용을 남기고 앱 업데이트를 기다리세요. |
| "삭제에 캡챠가 필요합니다" | 디시 모바일 웹에서 글 하나를 직접 지워 캡챠를 한 번 통과한 뒤 이어서 실행하세요. |
| 7일 뒤 앱이 안 열림 | 무료 Apple ID 서명이 만료된 것입니다. Sideloadly로 다시 설치하세요. |
| 앱을 닫으면 진행이 거의 안 됨 | iOS 백그라운드 제한 때문입니다. 앱을 켜 두거나, 사이드로드라면 지속 실행 모드를 고려하세요. |

## 개발자용

### 구조
```
src/
  app/               화면 (Expo Router, NativeTabs: 홈/프리셋/기록/설정)
  dc/                디시 프로토콜 (DcClient, 경로/패턴 설정, 차단 규칙표, 파서, 요청 한도)
  captcha/           캡챠 (외부 서비스 추상화, 수동 입력 시트)
  collect/           목록 수집
  presets/           프리셋 모델, 필터(순수 함수), 미리보기
  engine/            삭제 엔진, 체크포인트, 백업
  schedule/          스케줄 계산과 실행
  background/        BackgroundTask, 지속 실행 모드
  security/          앱 잠금, 재인증
  history/           이력, 통계
  debug/             디버그/크래시 로그
  shortcuts/         단축어 URL
  native/            위젯 / Live Activity 연결
  strings.ts         화면 문자열 (한국어)
  help/helpTexts.ts  (!) 도움말 문구
targets/widget/      위젯 + Live Activity 확장 (Swift)
native-modules/      Live Activity 네이티브 모듈 (위젯 빌드에서만 링크)
docs/dc-protocol.md  디시 요청/응답 조사 결과
docs/spec-addenda.md 원 사양 이후 추가된 규칙
```

디시 쪽 변경에 취약한 값(경로, 파라미터, 응답 필드, HTML 패턴, 차단 규칙)은 전부 `src/dc/` 안에 있고, 주석에 근거(조사 문서의 절 번호)가 달려 있습니다.

### 명령
```powershell
npm install
npm run typecheck
npm test
npm run check:icons
npx expo lint
npx expo-doctor
```

### 위젯 빌드가 기본 빌드와 다른 점
- `app.config.ts`는 환경 변수 `DC_APPLE_TARGETS=1`일 때만 `@bacons/apple-targets` 플러그인, App Group, `NSSupportsLiveActivities`를 넣습니다.
- 기본 빌드는 `package.json`의 `expo.autolinking.exclude`로 위젯 네이티브 모듈을 링크하지 않습니다. Actions의 위젯 잡은 이 설정을 바꾸고 `native-modules/`를 링크합니다.
- 단축어는 App Intents 대신 URL scheme(`dccleaner://`)으로 구현했습니다. App Intents는 Swift 네이티브 확장이 필요해 관리형 Expo 프로젝트에서 바로 만들 수 없기 때문입니다.
