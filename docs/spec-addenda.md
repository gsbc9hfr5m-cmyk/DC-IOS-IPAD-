# 사양 추가 사항 (원 사양 이후 받은 지시)

원 사양(0~6절)에 더해 지켜야 할 규칙이다. 원 사양과 충돌하면 이 문서가 우선한다.

## A. 네이티브 전용 (2026-11-26)
- 반드시 네이티브 앱으로 만든다. 웹앱, PWA, WebView 기반 UI, Capacitor/Ionic/Cordova 같은 하이브리드 래퍼는 쓰지 않는다. 모든 화면은 React Native 네이티브 컴포넌트로 구현한다.
- WebView는 reCAPTCHA나 Turnstile처럼 캡챠 통과가 불가피한 경우에만, 시트 안에서 최소한으로 쓴다.
- 디시와의 통신은 앱 안의 `fetch`로 직접 한다. 별도 웹 서버나 프록시는 두지 않는다. 앱은 기기 안에서만 동작한다.
- 설치된 앱은 브라우저 없이 단독으로 실행된다. 네트워크 요청은 디시인사이드와 캡챠 서비스로만 나간다.

## B. 아이콘 규칙 (2026-11-26)
- 아이콘은 전부 윤곽선(outline) 스타일이다. `expo-symbols`에서 `.fill` 변형은 쓰지 않는다.
- 선택된 탭이나 활성 상태도 채움으로 표시하지 않고 색과 굵기로만 구분한다.
- 아이콘 굵기는 regular로 통일한다. 이모지와 컬러 아이콘은 쓰지 않는다.
- 아이콘 색은 시스템 라벨 색(primary/secondary)과 틴트 하나만 쓴다.
- 구현: 심볼 이름은 `icons.ts` 한 곳에서 관리한다. 개발 중에 `.fill`로 끝나는 이름이 들어오면 assert로 막는다. 테스트에서도 앱 전체에 `.fill` 문자열이 없는지 검사한다.

## C. 2-17. 도움말 느낌표(!) 시스템 (2026-11-26)
- 설명이 필요한 모든 기능, 설정, 버튼 라벨 바로 옆에 윤곽선 느낌표 아이콘(`exclamationmark.circle`)을 둔다.
  - 예: "클리너 돌리기 (!)", "삭제 전 백업 (!)", "지속 실행 모드 (!)", "자동 일시정지 (!)", "캡챠 API 키 (!)"
- 동작
  - 느낌표를 누르면 리퀴드 글래스 팝오버(작은 카드)로 설명이 뜬다.
  - 바깥을 누르거나 스와이프하면 닫힌다.
  - 열릴 때 가벼운 햅틱을 준다.
  - 한 번에 하나만 열린다.
- 설명 문구에는 세 가지를 담는다.
  - 이 기능이 무엇인지 (한두 문장)
  - 켜거나 실행하면 실제로 어떻게 되는지
  - 주의할 점 (삭제는 되돌릴 수 없음, 배터리 소모, iOS 백그라운드 제한, 차단 가능성 등)
- 관리 방식
  - 문구는 전부 `helpTexts.ts` 한 파일에 키별로 모은다.
  - 화면에서는 `<HelpBadge id="..." />` 컴포넌트로 재사용한다. 코드 곳곳에 문구를 직접 쓰지 않는다.
- 위험도가 높은 기능(삭제 실행, 스케줄, 지속 실행 모드, 백업 OFF)은 느낌표 아이콘을 틴트 색으로 강조한다.
- 접근성: VoiceOver 라벨은 "도움말"로 하고, 터치 영역은 최소 44pt로 한다.
- 첫 실행 온보딩에서 "(!) 아이콘을 누르면 설명이 나옵니다"를 한 번 안내한다.

### 완료 기준 추가
- 모든 설정 항목과 주요 버튼 옆에 (!) 도움말이 있다. 누르면 글래스 팝오버로 설명이 나온다.
- 앱 전체에 채움(fill) 아이콘이 하나도 없고 윤곽선 아이콘만 쓰인다.

## E. 2-18. 방명록 삭제 (2026-11-26)
- 2-3 대상 종류는 복수 선택이다: 글 / 댓글 / 방명록
- 방명록 방향은 두 가지이고 각각 켜고 끌 수 있다.
  - 내가 남긴 방명록: 다른 사람 갤로그에 내가 쓴 글
  - 내 갤로그에 달린 방명록: 내 갤로그 방명록 중 삭제 권한이 있는 항목
- 연도 필터
  - 연도 복수 선택 (예: 2019, 2021만)
  - 범위 선택 (예: 2018~2020)
  - "N년 이전 전부"
  - 연도별 개수를 미리 보여준다.
  - 월 단위로 좁히기 (후순위)
- 방명록 전용 필터: 작성자 포함/제외, 키워드 포함/제외
- Dry-run: 연도별 삭제 예정 개수와 샘플을 보여주고 확인을 받는다.
- 아래 기능은 방명록에도 글/댓글과 똑같이 적용한다.
  - 보호 목록 (2-4)
  - 백업 (2-5): 작성자, 내용, 작성 시각
  - 삭제 엔진 (2-6)
  - 차단 감지 (2-7)
  - 기록 (2-14)
  - 통계 (2-13): "방명록"을 별도 항목으로 집계한다.
- 타인이 쓴 방명록은 삭제 권한이 확인된 항목만 대상으로 한다. 권한이 없거나 삭제 불가 응답이 오면 실패로 세지 않고 "권한 없음"으로 스킵한다.
- 삭제 가능 여부, 목록 수집 방법, 연도용 작성일 필드, 캡챠 요구 여부는 실제 요청 기준으로 조사해 dc-protocol.md에 적는다. 불가능한 방향은 옵션을 비활성화하고 보고한다.
- (!) 도움말을 붙인다. 예: "내가 남긴 방명록 (!)", "삭제 연도 (!)"
- 완료 기준: 연도(복수/범위/N년 이전)로 선택해 Dry-run → 백업 → 삭제까지 동작하고, 연도 밖 항목은 건드리지 않는다.

## D. 조사 결과에서 나온 설계 결정 (docs/dc-protocol.md 참고)
- 모든 요청에 모바일 UA를 보낸다.
- 요청 예산은 하나의 토큰 버킷으로 관리한다. 디시 한도가 약 20회/60초이므로 기본값은 요청당 4초 이상 간격이다.
- `del_limit`와 `comment_noti` 경고(매니저 차단 위험)는 자동으로 진행하지 않고 스킵한다.
